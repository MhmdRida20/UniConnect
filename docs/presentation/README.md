# FYP defence deck

`UniConnect_FYP_Presentation.pptx` (repo root) — 13 slides, 16:9, built for a
**10-minute** slot after the live demo.

Presentation slot: **Tuesday 18 August 2026, 14:00–14:50.**

---

## Rebuilding it

```
python docs/presentation/build_presentation.py
```

That regenerates icons, backgrounds and every slide, and overwrites the `.pptx`
at the repo root. **Edits made by hand in PowerPoint are lost on the next run** —
so either stop running the script once you start hand-editing, or make the change
in `build_presentation.py` instead.

| File | What it is |
| --- | --- |
| `build_presentation.py` | The whole deck. Content, layout and speaker notes. |
| `theme.py` | Backgrounds, shadows, transitions, animations. |
| `render_icons.py` | Pulls icons out of `Views/Shared/_Icons.cshtml` into PNGs. |
| `assets/` | Generated — icons, backgrounds, the framed screenshot. Safe to delete. |

Requires `python-pptx`, `matplotlib`, `numpy` and `Pillow`.

## Why it looks the way it does

- **Palette** is read straight from `wwwroot/css/site.css` — the same
  `#16a34a` primary, the same slate text, the same tints. The deck and the
  product are meant to read as one thing.
- **Icons are the product's icons.** `render_icons.py` parses the Hugeicons
  sprite the web portal already uses and redraws each symbol as a PNG. Nothing
  is from a stock icon set.
- **Font is Segoe UI**, not Inter. The site's stack is
  `'Inter', …, 'Segoe UI', …` — Inter is not installed here or on a typical
  university machine, so the deck uses the next member of the same stack rather
  than silently substituting something else.
- **Titles are capped at 60 characters** and the build raises if one is longer.
  A wrapped title collides with the accent rule and the first content row.

### The first and last slides

These two carry the most weight with a mixed audience, so they break the grid
the content slides share.

**Slide 1** is a two-column composition: type on the left, and on the right a
real product shot — the web dashboard in a browser chrome with the mobile Home
tab overlapping it in a device bezel. Both frames are generated by `theme.py`
from screenshots pulled out of the report, so the deck can never show a
different build of the app than the report does. For an audience that includes
families, seeing the actual product does more than any amount of type.

**Slide 13** is centred, unlike every other slide. The change of axis is what
makes it read as an ending rather than as one more content slide. The stat band
is a translucent panel so the background constellation reads through it as
glass, and it puts the headline numbers on screen at the moment the room is
paying most attention.

The soft glow behind the brand mark on slide 1 deliberately bleeds off the left
edge; PowerPoint clips it. That is the one shape in the deck that extends past
the canvas, and it is intentional.

### Motion

Every slide fades in, and content builds in waves — a card, a column or a step
at a time. **All of it runs automatically; nothing needs a click.** That is
deliberate: counting clicks to keep a slide in sync with a sentence is how a
rehearsed talk falls apart. You advance slides, and each slide plays itself.

The background motif is a node-and-edge constellation, because the argument of
the project is that UniConnect connects things that were previously siloed.

None of this exists in python-pptx — `theme.py` writes the OOXML directly
(`p:transition`, `p:timing`, `a:effectLst`). If you change that code and
PowerPoint offers to **"repair"** the file when opening it, the XML is malformed
and the effects have been silently dropped. Check with:

```
powershell -File <scratch>/check_anim.ps1
```

which asks PowerPoint itself how many effects survived. It should report 393
across 13 slides.

**To strip all motion** (some examiners dislike it): Transitions → None, applied
to all; and Animations → remove. Or delete the `set_transition` / `animate`
calls and rebuild.

### The weights chart on slide 7

Five bars, one colour. They are five parts of a single weighting, not five
entities that need their own identity, so a colour ramp would double-encode bar
length as hue and buy nothing. A green ordinal ramp was tried first and failed
validation — five monotone steps cannot satisfy both the step-gap and the
light-end contrast floor against a near-white card.

## Before you present

- [ ] **The deck says two-factor authentication is shipped; the report says it is
      future work.** Slide 9 lists TOTP with QR enrolment under "Enforced in the
      system", and it is no longer on slide 12. Make sure it is genuinely working
      before you present, and be ready for "the report calls this future work" —
      the honest answer is that it was completed after the report was submitted.
      Consider mentioning that in the talk rather than waiting to be asked.
- [ ] **Confirm the pill on slide 7.** It currently reads "Being adopted by our
      university for internship placement." Say only what is actually agreed —
      an examiner may ask who agreed it and when.
- [ ] **Decide the speaker split.** The notes suggest Speaker A on slides 1–5 and
      10–11, Speaker B on 6–9 and 12. Swap freely; just make the handoffs
      deliberate rather than improvised.
- [ ] **Rehearse against a clock.** See the timing table below — the script is
      1,423 spoken words, which is a genuine 10 minutes. There is no slack.
- [ ] **Record the backup demo video** — explicitly asked for in the briefing.
      Record it at the resolution of the presentation machine, not your laptop.
- [ ] **Export a PDF copy** as a fallback if PowerPoint misbehaves on the day.
- [ ] **Check the deck on the actual projector** if you can. The light slides use
      a `#f6f9f7` background that can look plain white on a dim projector — which
      is fine, but the muted body text at `#64748b` is the first thing to fade.
- [ ] Open in Presenter View so the speaker notes are visible to you only.

## Printing the script

The full speech is in the **speaker notes** of each slide.
File → Print → Full Page Slides → **Notes Pages** gives you a printable script
with each slide's thumbnail above its notes.

Slide 13's notes also carry six likely examiner questions with short answers.
